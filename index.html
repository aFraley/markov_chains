From Counting Letters to Modern AI

A hands-on tour through a century of ideas in machine learning — starting with a simple name generator built from scratch with NumPy, and tracing the same math all the way to modern AI.

Markov → Higher-Order → RNN → LSTM → Transformer → | CNNs → Applications → LLMs → Real World

Step 1 · 1906

Order-1 Markov Chain name_generator.py

The simplest possible approach: count how often each letter follows each other letter in the training data, then sample from those frequencies. Given the current character, pick the next one.

How it works
current char → lookup table → P(next char) → sample
The whole algorithm
P(next_char | current_char) = count(current → next) / count(current → anything)
What it teaches: You can generate surprisingly plausible text with nothing but character-pair statistics. No neural networks, no gradients, no training loops. Just counting.
The limitation: No memory beyond the current character. After generating "th", it sees only "h" and has no idea "t" preceded it. Names lack structure beyond local letter patterns.
Step 2 · Extension

Higher-Order Markov name_generator_higher_order.py

Instead of looking at just the last 1 character, look at the last N characters. Order-3 means "given the last 3 characters, what comes next?" This dramatically improves quality — but creates a new problem.

How it works (with backoff)
last N chars → lookup table → found? → yes: sample
↓ no: try N-1 chars → ... down to order-1
The backoff strategy
// Try "xqz" first, if never seen, try "qz", then "z" for order in [3, 2, 1]: context = name[-order:] if context in chain: return sample(chain[context])
What it teaches: More context = better predictions. "thr" almost always leads to vowels. But this comes at a steep cost.
The limitation: The state space explodes — 26N possible contexts. With only ~44 training names, most 3-character contexts are never seen. And even order-3 has no memory of the beginning of the name when generating the end. Still just counting, no generalization.
Step 3 · 1986

Recurrent Neural Network rnn_name_generator.py

Replace the lookup table with a neural network that learns a "hidden state" — a compressed summary of everything it has seen so far in the sequence. Even for character sequences never seen in training, the network produces reasonable predictions based on similar patterns.

The recurrence — hidden state feeds back into itself
xt → ht = tanh(Wxhx + Whhht-1 + b) → Whyh + b → softmax → P(next)
↑————— recurrence —————↳
The RNN — three lines of math
h = tanh(W_xh @ x + W_hh @ h + b_h) # update hidden state y = W_hy @ h + b_y # output logits p = softmax(y) # probabilities
What it teaches: A hidden state can compress an arbitrary-length history into a fixed-size vector. The network learns what to remember, not us. Trained with backpropagation through time (BPTT) — unrolling the recurrence and computing gradients all the way back.
The limitation — vanishing gradients: When computing gradients, the chain rule multiplies through Whh at every timestep. After 5-10 steps, gradients shrink exponentially toward zero. The network "forgets" the beginning of longer names.

Step 4 · 1997

Long Short-Term Memory lstm_name_generator.py

The LSTM adds a cell state that flows through time with additive updates instead of multiplicative ones. Three gates learn what to forget, what to store, and what to output. Gradients flow through the cell state without vanishing.

The cell state — the key difference from RNN
ct-1 → × ft → + it × gt → ct
forget gate controls erasure · input gate controls writing · additive, not multiplicative
The LSTM — four gates, eight lines
f = sigmoid(W_xf @ x + W_hf @ h + b_f) # forget gate i = sigmoid(W_xi @ x + W_hi @ h + b_i) # input gate g = tanh(W_xg @ x + W_hg @ h + b_g) # candidate values c = f * c_prev + i * g # cell state (THE KEY) o = sigmoid(W_xo @ x + W_ho @ h + b_o) # output gate h = o * tanh(c) # hidden state y = W_hy @ h + b_y # logits p = softmax(y) # probabilities
Why gradients don't vanish: During backprop, the gradient through the cell state is dct-1 = dct × ft. The forget gate ft is a learned value near 0 or 1 — not a matrix multiplication. No exponential shrinking. The cell state acts as a "gradient highway."
The limitation — still sequential: Characters must be processed one at a time, left to right. The 8th character can't be computed until characters 1-7 are done. And information from the start of the name still has to survive through every intermediate step — the highway helps, but it's still a chain.

Step 5 · 2017

Transformer transformer_name_generator.py

Drop recurrence entirely. Instead of passing information through a chain of hidden states, let every position attend directly to every earlier position through learned attention weights. The 8th character can look straight back at the 1st character — no intermediaries, no bottleneck.

Self-attention — every position attends to all previous positions
all chars → embed + position → Q, K, V → attention → FFN → softmax
all positions processed simultaneously · no recurrence · causal mask prevents looking ahead
Scaled dot-product attention
Q = X @ W_Q + b_Q # queries: "what am I looking for?" K = X @ W_K + b_K # keys: "what do I contain?" V = X @ W_V + b_V # values: "what do I offer?" scores = (Q @ K.T) / sqrt(d_k) + causal_mask # compatibility scores attn = softmax(scores) # attention weights out = attn @ V # weighted combination
Full transformer block (pre-norm, GPT-2 style)
X = embed(input) + positional_encoding # (T, 32) X_n = LayerNorm(X) # normalize X = X + MultiHeadAttention(X_n) # attend + residual X_n = LayerNorm(X) # normalize X = X + FFN(X_n) # feed-forward + residual logits = LayerNorm(X) @ W_out + b_out # project to vocab
What attention learns — example pattern for "achilles"
Brighter = stronger attention. Each row shows which earlier characters that position attends to. The causal mask prevents looking ahead (upper triangle is zero).
Why this matters: Attention gives O(1) depth between any two positions — the 10th character is one attention step away from the 1st. In an RNN, that's 9 sequential steps. This is the architecture behind GPT, Claude, and every modern large language model. Same math, 106× larger.
The tradeoff: ~44 training names is absurdly small for a transformer. We deliberately overfit to demonstrate the mechanism. In practice, transformers shine with thousands to billions of examples.

The Punchline

Every approach generates the same thing — Greek, Norse, and Celtic mythology names — from the same training data. The progression reveals a century of ideas about how to model sequential data:

Counting → frequency tables work, but can't generalize
Hidden state → neural networks compress history, but gradients vanish
Gating → additive cell state fixes gradients, but processing is sequential
Attention → direct access to everything, parallel processing, scales to GPT/Claude

The transformer in this project has ~14,590 parameters. GPT-3 has 175 billion. Claude has even more. But the core attention mechanism is identical — the same Q, K, V projections, the same scaled dot-product, the same softmax. The only differences are scale: more layers, more heads, more dimensions, more data.

The Bigger Picture

This project covers five points on a much larger map. Here's where everything fits in the full landscape of sequence modeling.

The Recurrent Family

All recurrent architectures share one trait: they process sequences step by step, carrying a hidden state forward. The differences are in how that state is updated and protected.

Architecture Year Key Idea In This Project?
Vanilla RNN 1990 Hidden state feeds back into itself via Whh Yes — Step 3
LSTM 1997 Cell state + 3 gates (forget, input, output) fix vanishing gradients Yes — Step 4
GRU 2014 Simplified LSTM — 2 gates (reset, update) instead of 3, similar results No — lateral move from LSTM, not a new concept
Bidirectional 1997 Run forward AND backward, concatenate both hidden states No — names are generated left-to-right
Stacked / Deep — Multiple RNN layers on top of each other for more capacity No — names are too short to benefit

The Spatial Branch: Convolutional Neural Networks

Everything above handles sequences — one character after another. But what about grid data like images, where spatial relationships matter? That's where CNNs come in. They're a parallel branch of deep learning that emerged alongside RNNs and eventually merged with transformers.

The core idea — a small filter slides across the input
A 3×3 filter detects one specific pattern (edge, curve, texture). Stack many filters to detect many features. Stack layers to detect features of features — edges become shapes become objects.
Convolution — the fundamental operation
# Slide a small filter (kernel) across the input # At each position, compute dot product: filter · patch for y in range(out_h): for x in range(out_w): patch = input[y:y+3, x:x+3] # 3×3 region output[y, x] = sum(patch * filter) # dot product # Same filter, same weights, applied everywhere = "weight sharing" # This is what makes CNNs efficient: a 3×3 filter has only 9 params # regardless of whether the image is 28×28 or 4096×4096
A typical CNN pipeline
image (28×28×1) ↓ Conv 3×3, 32 filters → ReLU # detect low-level features (edges) ↓ MaxPool 2×2 # shrink spatial dimensions by half ↓ Conv 3×3, 64 filters → ReLU # detect higher-level features (shapes) ↓ MaxPool 2×2 # shrink again ↓ Flatten # (7×7×64) → (3136,) vector ↓ Linear → softmax # classify
Key properties of CNNs:
Local connectivity — each neuron sees only a small patch, not the whole image.
Weight sharing — the same filter is applied everywhere, so a horizontal-edge detector works regardless of position. A 3×3 filter has 9 parameters whether the image is 100×100 or 10,000×10,000.
Translation invariance — a cat in the top-left activates the same features as a cat in the bottom-right.
Hierarchical features — early layers find edges, middle layers find shapes, deep layers find objects. Each layer builds on the one below it.
Architecture Year Key Idea Used For
LeNet 1989 First practical CNN — handwritten digit recognition Postal codes, checks
AlexNet 2012 Deep CNN + GPU training — won ImageNet by a landslide Kicked off the deep learning era
VGG 2014 Very deep (16-19 layers), only 3×3 filters — simplicity wins Image classification, feature extraction
ResNet 2015 Residual connections — skip connections let gradients flow through 150+ layers Everything. ResNet's skip connection is also in every transformer.
U-Net 2015 Encoder-decoder with skip connections — preserves spatial detail Medical imaging, segmentation, diffusion models
ResNet's residual connection — output = F(x) + x — is the same idea as the transformer's residual paths. It solved the same vanishing gradient problem for CNNs that LSTM solved for RNNs, and then transformers adopted it too. One idea, three architectures.

Two Dimensions of Intelligence

CNNs and RNNs aren't competitors — they solve different axes of the same problem. Many real-world systems combine both.

Spatial vs. temporal — and how they combine
Spatial image / frame → CNN → feature vector
Temporal feature sequence → RNN / LSTM → prediction
Combined video frames → CNN per frame → LSTM over time → action / anomaly
Video understanding, anomaly detection, autonomous driving, medical monitoring — anywhere you have sequences of structured data, CNN extracts "what" and RNN/LSTM tracks "when."
CNN RNN / LSTM Transformer
Operates on Grids (images, 2D maps) Sequences (text, time series) Both (with position encoding)
Core operation Convolution (local dot product) Recurrence (ht = f(ht-1, xt)) Attention (global dot product)
Receptive field Local → global via stacking All past (via hidden state) Global (every position, always)
Weight sharing Across spatial positions Across timesteps Across positions (learned)
Parallelizable? Yes No Yes
Key strength Spatial patterns, efficiency Sequential dependencies Long-range, any modality
The convergence: Modern Vision Transformers (ViT, 2020) replace CNNs with attention on image patches. The same attention mechanism from this project's text transformer now works on images too. The two tracks are merging — transformers are becoming the universal architecture for both spatial and temporal data.

Where It All Comes Together

These architectures rarely live in isolation. The interesting problems require combining them. Two examples that use nearly every concept covered above.

Text Recognition (OCR)

Reading text from images — scanned documents, street signs, license plates — is the literal intersection of spatial and sequential processing. You need to see the shapes (CNN) and understand them as a sequence of characters (RNN/Transformer).

Classic OCR pipeline — CRNN (CNN + RNN + CTC)
image of text → CNN → feature columns → BiLSTM → CTC decode → "HELLO"
CNN extracts visual features from each vertical slice. Bidirectional LSTM reads the sequence of slices left-to-right and right-to-left. CTC loss aligns variable-length output to variable-length labels without explicit segmentation.
The stages and what they use
# Stage 1: See the shapes (CNN — spatial) image (32×128×1) ↓ Conv layers extract features per vertical strip ↓ output: (1×32×512) — 32 positions, 512 features each # Stage 2: Read the sequence (BiLSTM — temporal) features (32×512) ↓ Forward LSTM: reads left → right ↓ Backward LSTM: reads right → left ↓ Concat: each position sees full left AND right context # Stage 3: Decode (CTC loss — alignment) per-position predictions → collapse repeated chars → remove blanks "HH-EE-LL-LL-OO" → "H-E-L-L-O" → "HELLO"
Every concept from this project appears here: CNN convolution and pooling (spatial features), LSTM with forget/input/output gates (sequential reading), bidirectional processing (context from both directions), softmax over a vocabulary (character prediction). Modern OCR systems (like TrOCR) replace the CNN+LSTM with a Vision Transformer encoder + text Transformer decoder — same task, attention all the way through.

Anomaly Detection

Learn what "normal" looks like, flag anything that deviates. The core idea is simple, but the architecture depends on what kind of data you have.

Data Type Architecture How It Works
Time series
sensor readings, server metrics		 LSTM autoencoder Encode normal sequences into a compressed state, decode back. High reconstruction error = anomaly. The LSTM's cell state tracks what "normal" temporal patterns look like.
Images
manufacturing defects, X-rays		 CNN autoencoder / GAN Train on normal images only. The CNN learns normal textures and shapes. Abnormal images reconstruct poorly — the error map highlights exactly where the defect is.
Video / thermal frames
surveillance, infrastructure monitoring		 CNN + LSTM CNN extracts spatial features per frame (what does this frame look like?). LSTM tracks temporal evolution (how are frames changing over time?). Anomaly = spatial appearance OR temporal pattern deviates from learned normal.
Text / logs
error logs, network traffic		 Transformer Self-attention over log sequences. Normal patterns form predictable attention weights. Unusual sequences produce high perplexity — the model is "surprised," which signals an anomaly.
Spatio-temporal anomaly detection — CNN + LSTM
frame1 frame2 frame3 ... framet
↓ each frame independently
CNN CNN CNN ... CNN same weights (shared)
↓ feature vectors
f1 → LSTM → f2 → LSTM → ... → LSTM → normal / anomaly
The CNN answers "what does this frame look like?" The LSTM answers "is this sequence of frames behaving normally?" Both must agree for the system to flag an anomaly, reducing false positives.
Anomaly scoring — the core idea
# Train on NORMAL data only model.fit(normal_sequences) # At inference, measure how "surprised" the model is prediction = model.predict(input_sequence) anomaly_score = reconstruction_error(input, prediction) # If the model can't reconstruct it, it's never seen anything like it if anomaly_score > threshold: flag_anomaly() # this is new / unusual
The connection to this project: The name generator learns "normal" character patterns for Greek, Norse, and Celtic names. If you fed it "Xzqwk," every model would assign extremely low probability — high "surprise" — because it violates learned patterns. That's anomaly detection. The same math that generates plausible names can also flag implausible ones. Generation and detection are two sides of the same coin.
Temperature as confidence: In our name generators, temperature controls how "confident" the model is in its predictions. Low temperature = conservative = only high-probability outputs. In anomaly detection, the equivalent is the threshold — how surprised does the model need to be before it flags something? Too sensitive = false alarms. Too lenient = missed anomalies. Same tradeoff.

The Transformer Family

The 2017 paper "Attention Is All You Need" introduced a single encoder-decoder architecture. It immediately split into three variants, each dominating a different domain.

Architecture Year Key Idea Used By
Encoder-Decoder 2017 Original transformer — encoder reads input, decoder generates output T5, translation models
Encoder-Only 2018 Drop the decoder. Bidirectional attention. Understands text, doesn't generate it. BERT, embeddings, classification
Decoder-Only 2018 Drop the encoder. Causal attention. Predict the next token. This is what LLMs are. GPT, Claude, LLaMA, Gemini
Mixture of Experts 2022+ Multiple FFN "experts" per layer, a router picks which to activate Mixtral, some GPT-4 variants
This project builds a decoder-only transformer — the same architecture class as GPT and Claude. Causal (left-to-right) attention, autoregressive generation: predict the next token, append it, repeat.
